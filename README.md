# 종목연구소

현재 제품 범위와 작업 순서는 [PRODUCT-PLAN.md](PRODUCT-PLAN.md)에 정리했습니다. 종목 추천·매매 할 일·개인 장부를 제공하는 앱이며 증권사 자동 주문 연결은 개발 범위에서 제외합니다. 아래의 기존 예비 실험 결과와 새로 설계할 알고리즘의 검증은 구분합니다.

[매매 노트 첫 기능 버전](DAILY-NOTE.md)을 추가했습니다. `node backend/daily-snapshot.mjs` → `node server.mjs` 후 `/daily.html`에서 최신 후보·매매 수량·입출금·체결 기록·백업을 사용할 수 있습니다. M1은 개발 기준이며 수익성 검증 완료나 전략 최종 채택을 뜻하지 않습니다. 장중 시세·원격 배포·자동 갱신은 아직 없습니다.

새 독립 후보인 [모멘텀 A v1](strategies/momentum/README.md)의 기본·변동성 조절 점수, 다음 거래일 종가 체결 연구 엔진과 검사를 구현하고 첫 실행을 마쳤습니다. 네 계좌 모두 미해결 보유 기업행사에서 중단돼 전기간 수익률은 산출하지 않았으며 선정 전략도 없습니다. 기존 화면에는 이 새 결과를 연결하지 않았습니다.

국내 개별 주식 전략 연구용 PWA입니다. 기본은 재현 가능한 **가상 24종목**이며 KRX 직접 수집기, 금융위원회 V2 대체 수집기와 실제 데이터 JSON 불러오기를 지원합니다. 데스크톱에 등록된 `KRX_API_KEY`로 약 2년의 실제 코스피·코스닥 자료를 수집하고 사전에 고정한 12개 전략의 개발·검증 예비 비교를 완료했습니다. 위험 기준을 만족하는 후보가 없어 전략을 선정하지 않았습니다. 실제 데이터는 비수정 가격의 예비 분석만 지원합니다. 증권사 연결 및 주문 기능은 구현되지 않았습니다. ETF·ETN API는 사용하지 않습니다.

과거 수집 확대 및 사전 고정한 후보의 개발·검증 비교는 아래 명령으로 진행합니다. Windows에 등록된 KRX 키는 자동 인식하며 수집을 재실행하면 일별 캐시를 재사용합니다.

```text
node backend/history-collector.mjs 2024-10-21 2026-10-20
node backend/research.mjs
```

계획은 `research-plan.json`에 고정합니다. 12개 후보를 동일 개발 구간에서 비교하고, 개발 MDD 30% 이내 중 개발 수익률 최대 후보를 선정한 뒤 검증 구간에서 평가합니다. 사용자 요청에 따라 현재는 수수료·체결가격 차이 0, 과거 매도 체결일별 거래세만 적용합니다. 이전 비용 결과는 `private-data/experiments/initial-costs/`에 보존합니다. 비용 변경으로 같은 검증 구간을 재사용했으므로 새로운 독립 검증은 아닙니다. 최대 120거래일을 공통 준비 구간으로 둡니다. 결과는 Git 제외 경로 `private-data/research-results.json` 및 `research-report.md`에 저장하며 앱의 '실제 데이터 · 최초 전략 비교'에서 확인할 수 있습니다. 증권사 주문 기능과 연결되지 않습니다.

## 데이터베이스와 증분 갱신

기존 원본 캐시를 SQLite로 옮겼습니다. 분석할 때는 다운로드하지 않고 DB에서 읽습니다. `node backend/db-update.mjs`는 한국 시각 전일까지의 새 날짜와 최근 며칠 정정만 확인합니다. 평일 14:30 갱신 예약을 등록했습니다. 데스크톱과 앱이 켜져 있어야 하며 첫 예약 실행은 확인 전입니다. 스키마·명령·업종 분류 준비 상태는 [DATABASE.md](DATABASE.md)에 설명했습니다.

공식 출처, 이용 조건, 수집 절차와 연구 한계는 [DATA-SOURCES.md](DATA-SOURCES.md)를 참고하세요.

## 종가 스코어링 연구 후보

사용자가 제공한 [원본 명세](strategies/claude-close/original.md)를 보존하고, 충돌하는 규칙을 정리한 [연구용 v1 결정사항](strategies/claude-close/DECISIONS.md)과 [설정](strategies/claude-close/v1.json)을 추가했습니다. 점수 계산·종목별 매매 의도·연구용 체결 확인 모듈과 테스트가 있으며, 전체 포트폴리오 백테스트 엔진과 앱 연결은 아직 없습니다. 위의 최초 12개 단순 모멘텀 전략 결과는 이 전략의 검증 결과가 아닙니다.

v1은 최초 1/3 매수, 실제 최초 체결 후 5·10거래일에 추가 매수 검토, 총 3회 상한을 사용합니다. 독립적인 비중 복구 매수는 끕니다. 손절은 우선 -15% 고정 연구값으로 비교하며 최적값이나 원본의 분포 기반 손절 구현을 뜻하지 않습니다. 신호는 T 종가, 체결 가정은 T+1 정규 종가로 기존 시가 체결 엔진과 구분합니다.

`node backend/scoring-readiness.mjs`로 필요한 저장 테이블과 준비 상태 보고서를 생성합니다. 현재 공시시점별 재무·수정 OHLC·기업행사·과거 업종 자료는 비어 있으므로 새 전략의 전체 백테스트와 실제 추천은 비활성 상태입니다. 선택 성장 지표만 결측 중립값 50을 허용하며 필수 자료를 임의로 대체하지 않습니다. 자료 검증 후 같은 모집단에서 규모 / 추세 / 규모+추세 / 전체 점수를 비교하고, 순차 구간 검증과 모의 운용을 진행합니다.

## 실행

Node.js가 설치된 환경에서 `npm run dev` 후 http://localhost:4173 에 접속합니다. 외부 패키지 설치는 필요 없습니다. 검증은 `npm test`, 문법 검사는 `npm run check`입니다.

npm이 없는 환경에서는 `node server.mjs`로 실행하고 `node --test`로 검증할 수 있습니다.

## 백테스트 규칙과 한계

- 전일 종가까지의 이동평균과 상승률로 순위를 계산하고 다음 거래일 시가에 체결합니다. 상승률 비교 기간 N은 N개 종가, 즉 N-1개 가격 변화입니다.
- 재편입일마다 전량 매도하고 목표 비중으로 재매수합니다. 정수 수량, 현금 잔액, 매수·매도 수수료, 매도세금, 불리한 방향의 체결가격 차이를 반영합니다. 조건 미충족 슬롯은 현금입니다.
- 앞 70%는 개발용, 뒤 30%는 검증용입니다. 검증 구간을 반복해서 보며 조정하면 검증 독립성이 사라집니다. 자동 최적화와 순차 구간 검증은 아직 없습니다.
- 비교선은 시작일 유효 시가 종목의 비용 없는 소수점 수량 균등보유입니다. 최종 자산은 마지막 확인 종가 평가이며 마지막 청산비용은 제외합니다.
- 기본 비용은 계산 예시이며 현행 세금이나 특정 계좌 수수료를 의미하지 않습니다.
- 가상 데이터는 주말만 제외하며 실제 한국 거래소 달력, 거래정지, 상하한가, 배당, 액면분할, 상장폐지, 유동성을 모델링하지 않습니다. 미래 성과나 실전 수익성의 근거로 사용할 수 없습니다.

## PWA와 GitHub

정적 파일을 HTTPS에서 제공하면 서비스워커로 앱 파일을 오프라인 캐시합니다. 설치 지원은 기기·브라우저별로 다르며 iOS용 아이콘 등은 후속 보완이 필요합니다. GitHub Pages에는 매매 노트 전용 산출물을 docs/ 경로로 배포합니다. 분석은 별도 접근 키로 암호화하며 원본 DB와 개인 장부를 제외합니다. 배포 진행 상태와 설정은 DEPLOYMENT.md를 참고하세요.

`backend/.env`는 로컬 서버·수집기에서 읽습니다. 브라우저에서는 읽지 않습니다. `.env` 및 `.env.*`, `private-data/`는 Git에서 제외합니다. 실제 키를 프런트엔드, 커밋, 채팅 또는 빌드 산출물에 넣지 않습니다. 개발 서버는 파일 허용 목록으로 `.env` 접근을 차단하고 루프백 주소에서만 실행합니다. 인증된 원격 서버 배포는 아직 수행하지 않았습니다.
